# Блок-схемы математических ядер двух ИС

Mermaid-диаграммы открываются на GitHub. Внизу каждой — формулы операций
с обычной математической нотацией.

---

## 1. Нечёткая логика (Fuzzy)

```mermaid
flowchart TD
    A["Входные данные:<br/>временной ряд N наблюдений<br/>(3 метрики + флаги качества)"] --> B{"Есть ли в ряду<br/>наблюдения с пропусками<br/>или экспертными оценками?"}
    B -->|"Да"| C["Отбрасываем всё до последнего<br/>такого наблюдения включительно.<br/>Остаётся точный хвост"]
    B -->|"Нет"| C2["Берём весь ряд"]
    C --> D{"В хвосте<br/>осталось<br/>≥ 2 точек?"}
    C2 --> D
    D -->|"Нет"| BLOCK["Система не выдаёт оценку:<br/>недостаточно точных данных"]
    D -->|"Да"| E["Для каждой метрики:<br/>оценить тренд (рост / падение)<br/>по корреляции значений со временем"]
    E --> G["Для последнего значения каждой метрики:<br/>вычислить степень принадлежности<br/>μ ∈ [0; 1] к каждому уровню L / M / H<br/>по трапециевидной функции"]
    G --> H["Отобрать термы с μ &gt; 0:<br/>(один или несколько уровней на метрику)"]
    H --> I["Подобрать в базе знаний правила,<br/>условия которых соответствуют<br/>отобранным термам по всем 3 метрикам"]
    I --> J["Каждое сработавшее правило → crisp-балл<br/>(см. схему 3)"]
    J --> K["Финальная оценка = среднее всех crisp-баллов.<br/>Зона: красная / жёлтая / зелёная"]

    style BLOCK fill:#fee,stroke:#c00
    style J fill:#cfe,stroke:#080
```

### Формулы

**Степень принадлежности (трапеция)** для значения `x` и параметров
`[a, b, c, d]`:

```
μ(x) = 0,                       если x ≤ a или x ≥ d
μ(x) = 1,                       если b ≤ x ≤ c    (плато)
μ(x) = (x − a) / (b − a),        если a < x < b
μ(x) = (d − x) / (d − c),        если c < x < d
```

**Корреляция (тренд):**

```
r = Σ(t_i − t̄)(y_i − ȳ)  /  √(Σ(t_i − t̄)² · Σ(y_i − ȳ)²)

тренд = «вверх», если r > −0.2; иначе «вниз»
```

(Порог сдвинут в отрицательную сторону: даже слегка отрицательная
корреляция читается как «вниз».)

## 2. Теория мультиопераций (Multiop)

```mermaid
flowchart TD
    A["Входные данные:<br/>временной ряд N наблюдений<br/>(3 метрики + флаги качества)"] --> B["Для каждой метрики:<br/>обобщить качество источника<br/>по всей истории"]
    B --> C["Если источник полностью точный или экспертный →<br/>оценить направление (рост / падение) по корреляции.<br/>Если в истории есть пропуски →<br/>направление считается неопределённым"]
    C --> D{"Направление<br/>метрики<br/>определено?"}
    D -->|"Да"| E1["Подать последнее значение метрики<br/>только в активное направление (↑ или ↓)"]
    D -->|"Нет"| E2["Подать последнее значение метрики<br/>в оба направления (↑ и ↓ одновременно)"]
    E1 --> F["Для каждого симптома базы знаний<br/>оценить состояние входного терма:<br/>см. таблицу состояний ниже"]
    E2 --> F
    F --> G["Для каждого правила (216 в базе)<br/>взять состояния трёх входных термов<br/>и применить операцию «и» (метаконъюнкция):<br/>получить состояние правила"]
    G --> H{"Состояние правила:<br/>подходит / может подходить /<br/>часть данных недоступна?"}
    H -->|"Нет<br/>(не подходит /<br/>может не подходить)"| SKIP["правило не идёт в среднее<br/>(но может быть показано в таблице)"]
    H -->|"Да"| J["Правило → crisp-балл<br/>(см. схему 3)"]
    J --> K["Финальная оценка = среднее всех crisp-баллов.<br/>Зона: красная / жёлтая / зелёная"]

    style J fill:#cfe,stroke:#080
    style SKIP fill:#eee,stroke:#888
```

### Состояния входного терма

Каждый симптом сравнивает значение с диапазоном `[start; end]`. Состояние
зависит от качества источника:

| Качество источника | Значение в диапазоне? | Состояние терма |
|---|:-:|:-:|
| Источник не дал данных | — | **0** (не квалифицирован) |
| Точные данные | ✓ | **2** (истинно) |
| Точные данные | ✗ | **1** (ложно) |
| Экспертная оценка | ✓ | **6** (истинно, источник частичный) |
| Экспертная оценка | ✗ | **5** (ложно, источник частичный) |
| Направление неопределено | — | **4** (один из источников недоступен) |

### Метаконъюнкция (операция «и» над состояниями)

Состояние правила = «и» от трёх состояний симптомов. Базовая таблица:

```
                   1 (ложно)   2 (истинно)   4 (неизвестно)
   1 (ложно)        1            1              1
   2 (истинно)      1            2              4
   4 (неизвестно)   1            4              4
```

Для составных состояний {3, 5, 6, 7} применяется обобщение через
множества (каждое состояние представимо как объединение базовых).

## 3. Расчёт crisp-балла одного правила (общий блок)

Этот блок одинаков для обеих систем. Различия — только в том, какие
правила в принципе попадают в этот расчёт.

```mermaid
flowchart TD
    A["Вход: правило базы знаний + последние<br/>значения 3 метрик"] --> B["Для каждой метрики:<br/>посчитать «определитель направления»<br/>— знак-нагруженное число,<br/>показывающее, насколько последнее значение<br/>отклонено от пика своего уровня"]
    B --> D["Совокупный определитель =<br/>взвешенная сумма трёх определителей.<br/>Веса: +1 для наёма и полноты, −1 для дефектов"]
    D --> E["Взять трапецию заключения<br/>правила (assessment level + trend)"]
    E --> F["Сдвинуть трапецию заключения<br/>в сторону «лучше» или «хуже»<br/>пропорционально совокупному определителю"]
    F --> G["Дефаззифицировать сдвинутую трапецию<br/>(привести к одному числу в [0; 100])"]
    G --> H["crisp-балл правила"]

    style F fill:#fec,stroke:#a60
    style G fill:#cfe,stroke:#080
```

### Формулы

**Определитель направления** (для значения `x` и трапеции `[a, b, _, c]`
по направлению «вверх»):

```
D(x) = (x − b) / (b − a),     если a < x ≤ b   (отрицательно)
D(x) = (x − b) / (c − b),     если b < x < c   (положительно)
D(x) = 0,                     иначе
```

Для «вниз» — зеркально, с компенсирующим сдвигом `−ρ` (для дефектов
`ρ = 0.25`).

**Совокупный определитель:**

```
DA = (ε_lh · D_lh + ε_c · D_c + ε_d · D_d) / 3,
где ε_lh = +1, ε_c = +1, ε_d = −1
```

**Сдвиг трапеции заключения** `[k, l, l, m]` на величину `|DA|` в
сторону цели `target`:

```
target = верхняя граница [m,m,m,m], если знак DA «улучшает» заключение
         нижняя граница  [k,k,k,k], если «ухудшает»

Bp_i = исходное_i + |DA| · (target_i − исходное_i)   для i = 1..4
```

**Дефаззификация** (приведение к числу) сдвинутой трапеции
`Bp = [a, b, _, d]` при горизонтальной отсечке `μ = 0.9`:

```
crisp = (μ · a + b + (2 − μ) · d) / 3
```

## 4. Соединительная схема: как два потока сходятся в общий расчёт

```mermaid
flowchart LR
    subgraph IN ["Входные данные"]
        DATA["временной ряд<br/>+ флаги качества"]
    end

    DATA --> F1
    DATA --> M1

    subgraph FUZZY ["Нечёткая логика"]
        F1["Обрезать ряд<br/>до точного хвоста"]
        F2["Тренд по хвосту"]
        F3["Степени принадлежности<br/>для последнего значения"]
        F4["Подобрать правила:<br/>все термы с μ &gt; 0"]
        F1 --> F2 --> F3 --> F4
    end

    subgraph MULTI ["Теория мультиопераций"]
        M1["Обобщить качество<br/>по всей истории"]
        M2["Тренд по полному ряду<br/>(или «неопределён»)"]
        M3["Состояние каждого симптома<br/>(значение ∈ диапазон + качество)"]
        M4["Состояние правил<br/>через метаконъюнкцию"]
        M1 --> M2 --> M3 --> M4
    end

    F4 --> CC["Для каждого активного правила:<br/>crisp-балл по общей формуле"]
    M4 --> CC

    CC --> SF["Финальная оценка fuzzy:<br/>среднее crisp"]
    CC --> SM["Финальная оценка multiop:<br/>среднее crisp"]

    style CC fill:#cfe,stroke:#080,stroke-width:3px
```

## 5. Где математика разная

| Этап | Нечёткая логика | Теория мультиопераций |
|---|---|---|
| Окно данных | только точный хвост | весь ряд |
| Корреляция считается | на хвосте | на полном ряду (если возможно) |
| Принадлежность к уровню | непрерывная (трапеция) | булева (значение ∈ диапазон) |
| На границе уровней | μ может быть 0 в соседних термах | оба соседних уровня могут активироваться (диапазоны пересекаются) |
| Эксперт на последней точке | блокировка | состояние правила = «может подходить» / «может не подходить» |
| Пропуск в истории | обрезка хвоста | состояние правила = «часть данных недоступна» |
| Когда нет результата | хвост короче 2 точек | ни одно правило не имеет подходящего состояния |

## 6. Где математика одинаковая

| Операция | Где применяется |
|---|---|
| Определитель направления | внутри расчёта crisp |
| Сдвиг трапеции заключения по определителю | внутри расчёта crisp |
| Дефаззификация | внутри расчёта crisp |
| Финальная агрегация | среднее crisp по «активным» правилам |
| Зонирование | ≤ 33.33 — красная, ≤ 66.66 — жёлтая, иначе — зелёная |

То есть **на одинаковых точных данных** обе системы дают идентичный
набор активных правил и идентичную оценку.
